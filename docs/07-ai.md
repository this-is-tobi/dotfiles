# AI Assistants (Claude Code & GitHub Copilot) & Model Context Protocol

This document explains the Claude Code / GitHub Copilot instructions and Model Context Protocol (MCP) server configuration included in this dotfiles repository. Both tools' shareable instructions/skills content is canonically sourced from the [tools repository](https://github.com/this-is-tobi/tools/blob/main/docs/02-ai.md) — this dotfiles repo only stores genuinely personal preferences (`.claude/settings.json`, `.vscode/settings.json`, `.vscode/mcp.json`) and wires the rest up via `setup-ai-agent.sh` at setup time.

## Claude Code

### Overview

Claude Code reads `CLAUDE.md` (repo) and `~/.claude/CLAUDE.md` (personal, always active — no opt-in setting needed, unlike Copilot). Since Claude Code has no per-file scoping, only tool-agnostic, always-relevant guidance goes in the personal file — the same "general" instructions used for Copilot, just without the `applyTo` frontmatter.

### Installation

**Automatic (during setup):** `./setup/setup-osx.sh` runs:
```sh
curl -fsSL https://raw.githubusercontent.com/this-is-tobi/tools/main/shell/setup-ai-agent.sh | bash -s -- -t claude -g -P
```
This creates `~/.claude/general-instructions.md`, adds an `@general-instructions.md` import line to `~/.claude/CLAUDE.md`, and installs the [Claude Code plugins](#plugins) at user scope (idempotent — safe to re-run).

**Manual installation:** same command, run directly.

### Settings (`.claude/settings.json`)

Dotfiles-owned, copied to `~/.claude/settings.json` during setup (this is genuinely personal preference, not shareable content, so it lives in this repo rather than the tools repo):

```json
{
  "hooks": {
    "PreToolUse": [
      { "matcher": "Bash", "hooks": [{ "type": "command", "command": "rtk hook claude" }] }
    ]
  },
  "effortLevel": "high",
  "attribution": { "commit": "" },
  "extraKnownMarketplaces": {
    "claude-plugins-official": {
      "source": { "source": "github", "repo": "anthropics/claude-plugins-official" }
    }
  },
  "enabledPlugins": {
    "claude-security@claude-plugins-official": true
  },
  "permissions": {
    "deny": [
      "Read(.env)",
      "Read(**/.env.*)",
      "Read(**/*.pem)",
      "Read(**/*.key)",
      "Read(**/secrets/**)",
      "Edit(.env)",
      "Edit(**/.env.*)",
      "Edit(**/*.pem)",
      "Edit(**/*.key)",
      "Edit(**/secrets/**)",
      "Read(~/.config/dotfiles/secrets.env)",
      "Edit(~/.config/dotfiles/secrets.env)",
      "Read(~/.claude.json)",
      "Edit(~/.claude.json)"
    ]
  }
}
```

- The `rtk hook claude` hook is the same auto-rewrite mechanism `rtk init -g` installs — token-optimized shell command output, no prompt-level instructions needed.
- `attribution.commit: ""` disables the `Co-Authored-By: Claude` commit trailer.
- `permissions.deny` blocks the `Read`/`Edit` tools from ever touching secret-shaped paths, on every machine this file gets deployed to — same rules as the per-project template in [tools repo's `ai/claude/config/settings.json`](https://github.com/this-is-tobi/tools/blob/main/ai/claude/config/settings.json), applied globally here instead of opt-in per repo. It does **not** stop the `Bash` tool from `cat`-ing the same files — see the [tools repo's Secrets & Permission Scoping section](https://github.com/this-is-tobi/tools/blob/main/docs/02-ai.md#secrets--permission-scoping) for that caveat and the direnv-based complement to it.
- The `~/.config/dotfiles/secrets.env` and `~/.claude.json` rules keep the `Read`/`Edit` tools away from the local secrets file (see [Managing Secrets](#managing-secrets)) and from the file holding the MCP server definitions.
- `enabledPlugins` + `extraKnownMarketplaces` register the [Claude Code plugins](#plugins) below. These two keys are **load-bearing in this file specifically**: `claude plugin install` writes them into `~/.claude/settings.json`, and the setup scripts `cp` this file over that path — so without them here, every setup re-run would silently uninstall the plugin. Declaring them means the copy carries the registration instead of dropping it, and `setup-ai-agent.sh -P` (which runs after the copy) materializes the plugin files and updates them.

### Plugins

Installed at user scope by `setup-ai-agent.sh -P` during setup, so they're available in every repo without per-project opt-in:

| Plugin                                    | Purpose                                                                                                                   |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `claude-security@claude-plugins-official` | On-demand multi-agent vulnerability scan (`/claude-security`), with adversarially-verified findings and reviewed patches |
| `superpowers@claude-plugins-official`     | Jesse Vincent's skills library (TDD, brainstorming, plan writing/execution, parallel-agent workflows, and more)          |

Both cheap to keep around — ~642 and ~688 tokens always-on respectively, and nothing runs until invoked (skills) or requested (`/claude-security`). `claude-security` requires a paid plan with dynamic workflows enabled and `python3` ≥ 3.9.6; `superpowers` has no special requirements. Full rationale, usage, and the deliberate exclusion of the `security-guidance` plugin are in the [tools repo's Plugins section](https://github.com/this-is-tobi/tools/blob/main/docs/02-ai.md#plugins).

**Manual install / verify:**
```sh
curl -fsSL https://raw.githubusercontent.com/this-is-tobi/tools/main/shell/setup-ai-agent.sh | bash -s -- -t claude -g -P
claude plugin list
```

### RTK (Rust Token Killer)

`rtk init -g` (run automatically by the setup scripts, before `.claude/settings.json` is copied into place) generates `~/.claude/RTK.md` and adds the `@RTK.md` import to `~/.claude/CLAUDE.md`. See the [tools repo's RTK section](https://github.com/this-is-tobi/tools/blob/main/docs/02-ai.md#token-efficient-terminal-commands-rtk) for details.

### Custom Agents

Not installed by default. To add them:
```sh
curl -fsSL https://raw.githubusercontent.com/this-is-tobi/tools/main/shell/setup-ai-agent.sh | bash -s -- -t claude -g -a
```

## GitHub Copilot Instructions

### Overview

GitHub Copilot instructions are specialized markdown files that guide Copilot's behavior for specific tasks:
- **Code generation** - Language and framework best practices
- **Commit messages** - Conventional commit formatting
- **Pull request descriptions** - PR template compliance
- **Code review** - Review checklists and standards

### Installation

The setup scripts install Copilot's personal instructions and skills via the [tools repository](https://github.com/this-is-tobi/tools/blob/main/docs/02-ai.md)'s `setup-ai-agent.sh`:

**Automatic (during setup):**
```sh
# Instructions are installed automatically
./setup/setup-osx.sh
```

**Manual installation:**
```sh
curl -fsSL https://raw.githubusercontent.com/this-is-tobi/tools/main/shell/setup-ai-agent.sh | bash -s -- -t copilot -g -c
```

#### copilot-instructions.md

**Purpose:** Universal development guidelines

**Location:** `~/.copilot/instructions/general.instructions.md`

    { "file": "~/.copilot/instructions/general.instructions.md" }
  ]
}
```

**Purpose:** Conventional commit message generation

**Location:** `~/.copilot/instructions/commit-message.instructions.md`

**Content:**

- Commit type definitions (feat, fix, docs, etc.)
- Scope guidelines
- Breaking change handling
- Commit message examples by type
- Multi-commit scenarios
- Best practices for atomic commits

**Format enforced:**

[optional footer(s)]
```

**Usage in VS Code:**
```json

**Examples:**

docs(readme): add installation instructions

```

### Using Copilot Instructions

#### Generating Commit Messages

1. Stage your changes: `git add .`
2. In VS Code, use Copilot Chat: `/commit`
3. Copilot generates conventional commit message
4. Review and accept or modify

**Example:**
```
You: /commit
Copilot: feat(auth): add OAuth2 authentication support

Implements OAuth2 authentication flow with support for
Google and GitHub providers. Includes token refresh logic
and secure session management.

BREAKING CHANGE: replaces existing basic auth system
```

#### Generating PR Descriptions

1. Create PR in VS Code or web
2. Use Copilot to generate description
3. Copilot checks for templates and formats appropriately

**Example:**
```markdown
## Summary
Adds OAuth2 authentication support with Google and GitHub providers.

## Changes
- Implement OAuth2 flow
- Add token refresh mechanism
- Update authentication middleware

## Breaking Changes
⚠️ This replaces the existing basic authentication system

## Related Issues
Closes #123
```

#### Code Review

1. Select code in editor
2. Use Copilot Chat: `@workspace /review`
3. Copilot provides structured review with priorities

**Example:**
```
P0 (Critical):
- Missing input validation on user email (security)

P1 (Important):
- Database query in loop (performance)
- No error handling for API call

P2 (Moderate):
- Missing unit tests for new function
- Consider extracting magic number to constant

P3 (Minor):
- Add JSDoc comment
- Variable name could be more descriptive
```

## Model Context Protocol (MCP)

### Overview

MCP provides standardized access to external tools and data sources for AI assistants. This dotfiles repo configures the same set of servers for both Claude Code (registered at user scope by [`setup/helpers/claude-mcp.sh`](../setup/helpers/claude-mcp.sh), which the setup scripts run) and VS Code Copilot (`.vscode/mcp.json`) — `github` is the one exception, since it authenticates via the VS Code Copilot session and has no equivalent for Claude Code.

### Managing Secrets

Secrets live in one local file, `~/.config/dotfiles/secrets.env`, and need no CLI, secret manager or wrapper. The first time the setup copies the dotfiles it creates that file from [`secrets.env.example`](../dotfiles/.config/dotfiles/secrets.env.example) with mode `600`, and it never overwrites it afterwards. The file holds plain `KEY=value` lines; `env.sh` (managed by the setup, don't edit it) loads it into every zsh session.

Each tool then picks the secrets up through its own standard mechanism:

| Consumer                                 | How it gets the secret                                                                                              |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Shell and CLIs (`vault`, `argocd`, mise) | exported from `secrets.env` by `env.sh`                                                                             |
| Claude Code MCP servers                  | `${VAR}` references stored in `~/.claude.json`, expanded from the environment when Claude Code starts                |
| VS Code MCP servers                      | `inputs` in `mcp.json`: VS Code asks once per value (`password: true` hides it) and stores it securely               |
| Continue                                 | `${{ secrets.NAME }}` in `config.yaml`, resolved from `~/.continue/.env`                                             |
| A single project                         | [direnv](https://direnv.net): `dotenv_if_exists .env.local` in the project's `.envrc`, with `.env.local` git-ignored |

Keep in `secrets.env` only what you want in every shell: every program you start, AI agents included, inherits it. Project-specific keys belong in that project's `.env.local`, loaded by direnv only inside the project. The file is sourced by the shell, so a secret manager stays optional: a line like `CONTEXT7_API_KEY=$(your-tool get context7)` works if you prefer fetching values from one.

Deny rules in `.claude/settings.json` keep Claude Code's `Read`/`Edit` tools away from `secrets.env` and `~/.claude.json` (see [Settings](#settings-claudesettingsjson)).

### Configured Servers

#### GitHub MCP Server

**Type:** HTTP

**Purpose:** GitHub API integration (repos, PRs, issues, code search, Actions)

**Configuration (`.vscode/mcp.json`):**
```json
{
  "github": {
    "type": "http",
    "url": "https://api.githubcopilot.com/mcp/"
  }
}
```

**No setup required** - uses your VS Code GitHub authentication. **Copilot (VS Code) only** — Claude Code has its own native GitHub integration via the `gh` CLI instead.

#### Context7 MCP Server

**Type:** HTTP

**Purpose:** Up-to-date library and framework documentation

**Configuration (`.vscode/mcp.json`):**
```json
{
  "context7": {
    "type": "http",
    "url": "https://mcp.context7.com/mcp",
    "headers": {
      "CONTEXT7_API_KEY": "${input:context7-api-key}"
    }
  }
}
```

`context7-api-key` is a `promptString` input (`password: true`) declared in the same file: VS Code asks for the key the first time the server starts and stores it securely.

**Claude Code setup** (done automatically by the setup scripts):
```sh
claude mcp add --transport http context7 https://mcp.context7.com/mcp -H 'CONTEXT7_API_KEY: ${CONTEXT7_API_KEY}' -s user
```

> [!WARNING]
> The single quotes around `${CONTEXT7_API_KEY}` are load-bearing — they stop the shell from expanding the variable before `claude mcp add` sees it. Double-quoting would bake the *current* secret value into `~/.claude.json` as plaintext instead of storing the `${VAR}` reference for Claude Code to expand at runtime.

**Setup required:**
1. Get an API key at [context7.com](https://context7.com/)
2. Add to `~/.config/dotfiles/secrets.env` (Claude Code reads it from the environment):
```sh
CONTEXT7_API_KEY=your_api_key_here
```
3. Restart the terminal and any running Claude Code sessions. VS Code asks for the key the first time the server starts.

#### Kubernetes MCP Server

**Type:** stdio (npx)

**Purpose:** Kubernetes cluster management (pods, services, deployments, logs, events)

**Configuration (`.vscode/mcp.json`):**
```json
{
  "kubernetes": {
    "type": "stdio",
    "command": "npx",
    "args": ["-y", "kubernetes-mcp-server@latest"]
  }
}
```

**Claude Code setup:**
```sh
claude mcp add kubernetes -s user -- npx -y kubernetes-mcp-server@latest
```

**Setup required:** `~/.kube/config` must exist, be valid, and point at a reachable cluster.

#### ArgoCD MCP Server

**Type:** stdio (npx)

**Purpose:** List/sync/inspect ArgoCD applications

**Configuration (`.vscode/mcp.json`):**
```json
{
  "argocd": {
    "type": "stdio",
    "command": "npx",
    "args": ["-y", "argocd-mcp@latest", "stdio"],
    "env": {
      "ARGOCD_BASE_URL": "${input:argocd-base-url}",
      "ARGOCD_API_TOKEN": "${input:argocd-api-token}"
    }
  }
}
```

**Claude Code setup** (registered only when `ARGOCD_BASE_URL` is set in `secrets.env`):
```sh
claude mcp add argocd -s user -e ARGOCD_BASE_URL='${ARGOCD_BASE_URL}' -e ARGOCD_API_TOKEN='${ARGOCD_API_TOKEN}' -- npx -y argocd-mcp@latest stdio
```

> [!WARNING]
> Same reason as the Context7 command above — single-quote the `${...}` references so the literal reference is stored, not the expanded secret.

**Setup required:** the server URL and an ArgoCD API token (Settings > Accounts > Generate Token). For Claude Code, set `ARGOCD_BASE_URL` and `ARGOCD_API_TOKEN` in `~/.config/dotfiles/secrets.env`, then re-run `setup/helpers/claude-mcp.sh`. VS Code asks for both the first time the server starts. Remove the server from `mcp.json` if you don't use ArgoCD.

#### Playwright MCP Server

**Type:** stdio (npx)

**Purpose:** Browser automation (navigate, click, screenshot, fill forms)

**Configuration (`.vscode/mcp.json`, registered as `microsoft/playwright-mcp`):**
```json
{
  "microsoft/playwright-mcp": {
    "type": "stdio",
    "command": "npx",
    "args": ["-y", "@playwright/mcp@latest"]
  }
}
```

**Claude Code setup** (registered as `playwright`):
```sh
claude mcp add playwright -s user -- npx -y @playwright/mcp@latest
```

**Setup required:** none beyond Node/npx being available.

### Adding Custom MCP Servers

#### Finding MCP Servers

Browse available servers:
- [Awesome MCP Servers](https://github.com/punkpeye/awesome-mcp-servers)
- [MCP Registry](https://mcp-registry.org/)
- Community repositories

#### Adding a Server

1. **Edit `.vscode/mcp.json`:**

```json
{
  "my-server": {
    "type": "stdio",
    "command": "node",
    "args": ["/path/to/server.js"]
  }
}
```

2. **Server types:**

**stdio** (Standard Input/Output):
```json
{
  "type": "stdio",
  "command": "node",
  "args": ["server.js"]
}
```

**http** (HTTP Endpoint):
```json
{
  "type": "http",
  "serverUrl": "https://api.example.com/mcp"
}
```

**sse** (Server-Sent Events):
```json
{
  "type": "sse",
  "serverUrl": "https://api.example.com/sse",
  "headers": {
    "Authorization": "Bearer ${API_TOKEN}"
  }
}
```

**docker** (Docker Container):
```json
{
  "type": "docker",
  "args": {
    "image": "my-mcp-server:latest",
    "volumes": ["/host/path:/container/path:ro"]
  }
}
```

3. **Restart VS Code** to load new server

### Troubleshooting

#### Copilot Instructions Not Applied

**Check file paths:**
```sh
ls -la ~/.copilot/instructions/
```

**Verify VS Code settings:**
```sh
code ~/.vscode/settings.json
# Ensure paths use absolute notation starting with ~
```

**Reload instructions:**
1. Restart VS Code
2. Or reload window: `Cmd+Shift+P` → "Reload Window"

#### MCP Server Connection Failed

**Check server status:**
1. `Cmd+Shift+P` → "MCP: Show Server Status"
2. Review error messages

**Common issues:**

**Missing environment variables:**
```sh
# Verify in terminal
echo $CONTEXT7_API_KEY

# Add to secrets.env if missing
vim ~/.config/dotfiles/secrets.env
```

**Docker not running:**
```sh
# Start Docker Desktop
open -a Docker

# Verify
docker ps
```

**Invalid Kubernetes config:**
```sh
# Test cluster access
kubectl cluster-info

# Update config if needed
```

#### Copilot Not Using MCP Servers

**Explicitly mention the server:**
```
You: Using GitHub MCP, what's the status of PR #42?
```

**Check Copilot settings:**
- Ensure Copilot is enabled
- Verify MCP integration is active
- Check network connectivity

## Best Practices

### Instruction Files
- Keep instructions concise and actionable
- Update instructions as practices evolve
- Use project-specific instructions when needed
- Share instructions with team

### MCP Servers
- Only enable servers you actively use
- Use read-only volumes for security
- Rotate API keys regularly
- Monitor server performance
- Keep Docker images updated

### Security
- Never commit API keys to git
- Keep secrets in `secrets.env` (or VS Code `inputs`), never in a committed file
- Review MCP server permissions
- Use minimal necessary scopes
